# d8 fused-GEMM arm — measured, and promoted to default (2026-09-07)

The d8-K16384 arm was written, numerically gated at the exact flagship
geometry, and shipped `DEFAULT OFF` for one reason: nobody had ever run it.
Correctness was never the question — `test_gemmseg_cbdev_numeric` has gated
d8 at K16384 and K4096 since the kernel landed. The blocker was that the
only local d8 artifact (Flash-2.1) needs `qwen4_exp`, which our gate venv's
mlx-lm 0.31.3 cannot load, and the other (the 397B) is 107 GB.

Both are now measured.

## Numbers

| artifact | placement | d8 modules fused | OFF | ON | gain |
|---|---|---|---|---|---|
| 397B-2.2 | 2-node ring | 151 (29/180 -> 180/180) | 25.184 s / 275 tok/s | 19.489 s / 355 tok/s | **1.29x** |
| Flash-2.1 | M3 single-box | 92 (6/144 -> 98/144) | 15.190 s / 458 tok/s | 11.587 s / 601 tok/s | **1.31x** |

Identical prompt within each pair (6919 and 6961 tokens), 5 reps plus an
untimed warm pass, min and median both reported. Rep spreads: 397B 5.4% /
3.9%, Flash 4.5% / 1.2%. Rep ranges do NOT overlap in either pair — the
slowest fused rep beats the fastest legacy rep both times.

Two artifacts, two topologies, agreeing within 0.02x.

**Trust the Flash number more.** It is single-box, so there is no pipeline
to confound it and no ring latency in the measurement, and its ON arm has a
1.2% spread. The 397B number rides the 2-node ring, which is noisier.

## Caveat on method — weaker than the d2/d4 benches

`VQ_MOE_FUSED_GEMM_D8` is read at import, so flipping it needs a process
restart. Unlike the d2/d4 arms, these two could NOT be interleaved inside
one process: they are separate loads, minutes apart. The margins are 3-25x
the observed spread so the direction and rough size hold, but the exact
ratio is softer than an interleaved measurement and should be labelled that
way wherever it is quoted.

## Perplexity gate — PASSED 2026-09-08

The correctness evidence the promotion shipped without. Flash-2.1 (the
practical d8 artifact: 48 GB vs the 397B's 107 GB, identical d8-K16384
CB_DEV geometry, so it gates the same code path), scored under exo's env
(mlx-lm 0.31.9 — our gate venv's 0.31.3 cannot load qwen4_exp), chunk 512,
`VQ_FUSED_MAX_N=1` to force the prefill path:

| arm | ppl | nll/token |
|---|---|---|
| d8 OFF (legacy) | 6.9816 | 1.943281 |
| d8 ON (fused) | **6.9794** | 1.942967 |

delta **-0.0022 ppl (-0.032%)** on an identical 8192 tokens — inside the
float-reordering band, and marginally better, matching the d4-K8192
promotion's 5.5041 -> 5.4966.

NOT a speed result: the scorer runs streaming-1box from disk at chunk 512,
so its wall-clock (46.7 s fused vs 39.1 s legacy) is dominated by I/O and
per-chunk overhead, not the prefill kernel. Speed comes from the 9k-token
benches above.

## The NSUB=80 gap — found while confirming coverage, NOT yet addressed

With d8 armed, Flash-2.1 reports 98/144, not 144/144:

    OK   92 x d8 K16384 G64 bits14   gemmseg v2   CB_DEV, packed
    ->   46 x d8 K16384 G64 bits14   legacy       NSUB=80 not a multiple of 32
    OK    6 x d2 K256   G64 unpacked gemmseg v2   threadgroup, unpacked

46 of the 138 d8 modules have `in=640`, so `NSUB = 640/8 = 80`, and
`gemmseg_fits` requires `(IN // D) % 32 == 0`. They stay legacy — correct,
just not accelerated.

This was INVISIBLE before the promotion: with d8 unarmed, coverage lumped
all 138 modules under "d8 arm unarmed" and the NSUB constraint never
surfaced. Any earlier statement that arming d8 takes Flash-2.1 to 144/144
was wrong; the real move is 6 -> 98. The 1.31x above is therefore the gain
from fusing 92 modules, not 138 — a better per-module result than it looks,
and it means there is headroom left on this artifact specifically.

Whether the 32-multiple constraint can be relaxed for a tail segment is
unexamined. It is a real remaining opportunity on the ONLY artifact in the
fleet that is not now 100% fused.

## Fleet coverage after promotion

Every MoE artifact is 100% fused except Flash-2.1 (98/144, above):
GLM 2.7/3.1/3.6 = 126/126; 397B 2.2 = 180/180, 2.4/2.6/3.1 = 171/171;
35B 3.4/3.8/4.6/5.4 = 120/120; Flash 3.2/4.4/5.5 = 144/144;
gemma-26b = 90/90. The 27B rungs are dense (wdec + GEMM, gemmseg is
MoE-only by construction).

## What changed in the tree

- `vq_switch.py`: `_FUSED_GEMM_D8` default "0" -> "1", with the measurement
  and the method caveat recorded at the flag.
- `test_gemmseg_d8_armed_by_default`: ratchets the promotion, and is
  mutation-verified (flipping the default back makes it fail).
- 19/19 in `test_vq_prefill_paths.py` pass with d8 armed.

## NOT done here

Published artifacts carry their OWN bundled `model.py`, whose `_FUSED_GEMM_D8`
default is still "0". **This promotion changes nothing for anything already
published** until those artifacts are rebundled and republished — a separate,
deliberately gated step that is Noah's call, not an automatic consequence of
this measurement. The cluster currently gets the armed path only because
`VQ_MOE_FUSED_GEMM_D8=1` is set in `~/.exo/exo-env.sh` on both nodes.
